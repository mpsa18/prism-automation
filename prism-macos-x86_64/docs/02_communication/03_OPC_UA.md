# OPC UA Client & Server Gateway

## Overview
Prism embeds an industrial OPC UA gateway built on the asynchronous `async-opcua` stack:
- **OPC UA Server:** Exposes internal active tags directly to plant historians, SCADA systems, and diagnostic clients (e.g., UaExpert) at `opc.tcp://<host>:4840/`.
- **OPC UA Client:** Polls and writes to external third-party OPC UA servers.

Both sides are declared in `config/02_northbound/02_opc_server/server.toml` — the runtime OPC UA
configuration file (legacy fallback: `config/opc.toml`). The exported set comes
from two sources, both validated against the device tree before startup:

- `[[server.tag]]` blocks in `server.toml` — hand-written exports;
- `config/02_northbound/02_opc_server/nodes.toml` (plus every `*.toml` under `config/02_northbound/02_opc_server/nodes.d/`, recursively — the split layout writes one file per device) — the address space generated by
  `prism-devtools generate opc-server` (`[[node]]` entries, merged into the
  exports at load; an explicit `[[server.tag]]` wins on duplicates).

`config/02_northbound/04_opc_client/endpoints.toml` is a generator workspace/artifact (the bench
uses it for its inventory): the runtime OPC UA *client* devices are declared as
`[[device]] protocol = "opcua"` in the device tree (section 2).

## 1. OPC UA Server Configuration (`config/02_northbound/02_opc_server/server.toml`)

```toml
[server]
enabled            = true
host               = "127.0.0.1"         # loopback: unencrypted is OK; remote setup - section 4
port               = 4840
endpoint_path      = "/"
namespace_uri      = "urn:prism:tags"
pki_dir            = "../data/pki/server"
security_policy    = "None"             # None | Basic256Sha256
security_mode      = "None"             # None | SignAndEncrypt
# certificate      = "../data/pki/server/cert.pem"  # required pair for encrypted security
# private_key      = "../data/pki/server/key.pem"
allow_anonymous    = true
allow_anonymous_writes = false           # writes require an authenticated session
# allow_insecure_remote = true           # explicit ack: policy None on a non-loopback host
update_interval_ms = 100
write_timeout_ms   = 5000

# Optional username identities (require encrypted security)
# [[server.user]]
# username     = "engineer"
# password_env = "PRISM_OPC_PASSWORD"

# ── Exported tags ──────────────────────────────────────────────────────────
# Hand-written exports; generated ones live in nodes.toml (see section 3).
[[server.tag]]
tag      = "io_controller.flow_sp"     # bus ID <device>.<tag>
node_id  = "ns=2;s=stand.flow_sp"      # optional; defaults to the tag id
writable = true

[[server.tag]]
tag      = "calculations.pressure_drop"
writable = false
```

### `[server]` key reference
- `enabled`: Start the server (default `false`).
- `host` / `port` / `endpoint_path`: Endpoint address (`endpoint_path` must start with `/`).
- `namespace_uri`: OPC UA namespace for exported nodes.
- `pki_dir`: Certificate store directory, resolved from the `config/` root (default `../data/pki/server`).
- `security_policy` / `security_mode`: Supported pairs are `None`/`None` and `Basic256Sha256`/`SignAndEncrypt` (the secure pair requires `certificate` + `private_key`).
- `allow_anonymous`: Permit anonymous clients. If `false`, at least one `[[server.user]]` is required.
- `allow_anonymous_writes`: Permit **writes** from anonymous sessions (default `false` — writes require authentication; see section 4).
- `allow_insecure_remote`: Explicit acknowledgement required to bind a non-loopback `host` with `security_policy = "None"`.
- `[[server.user]]`: `username` + `password_env` (name of an environment variable holding the password). Username authentication requires encrypted security.
- `update_interval_ms`: Value update cadence.
- `write_timeout_ms`: Timeout for write requests.

### `[[server.tag]]` exports
- `tag`: Bus ID of the exported tag. Must reference a readable, typed tag; `writable = true` additionally requires `access = "rw"`.
- `node_id`: Optional explicit NodeId. Values with a UA prefix (`ns=2;s=...`, `i=...`) are parsed as full NodeIds; a bare value is a string identifier inside the prism namespace (the default is the tag id).
- `writable`: Allow OPC UA clients to write through to the tag.

### Generated exports (`config/02_northbound/02_opc_server/nodes.toml` / `nodes.d/`)
`prism-devtools generate opc-server` writes the full address space here
(`[defaults]` + one `[[node]]` per tag: `tag`, `node_id`, `writable`,
`sampling_interval_ms`, `queue_size`, `discard_oldest`). With
`[generator].layout = "split"` the file keeps only `[defaults]` and each device
gets its own `nodes.d/<device>.toml`; the runtime merges both forms (files
sorted, `nodes.toml` first, the first entry of a tag wins). At load the runtime
merges the `[[node]]` entries into the server exports; the monitoring fields and
`[defaults]` are accepted for compatibility (the SUT serves client-driven
subscriptions and does not use them — the bench reads them for its inventory).
Tags the runtime cannot serve are not generated: write-only (`wo`) tags and tags
without `data_type` are skipped with a warning by the generator, and any export
that does not resolve fails `--check-config` and the server start. To keep the
generated file valid, edit the generator config
(`devtools/tooling/generators/opc_server.toml`), not `nodes.toml`.

String tags (`data_type = "string"`) are exported as OPC UA `String`
variables: reads return `Variant::String` (an empty string instead of a
`Variant::Empty` NULL, which crashes naive clients), writes accept a string or
scalar and are forwarded to the device as text (no scale conversion).
Virtual string tags are served from the store, so a tag with an empty value
reads as an empty string with `BadNoData`.

## 2. OPC UA Client Configuration (Runtime)

Remote OPC UA servers are declared as devices (`protocol = "opcua"`) in their
own southbound folder — `config/01_southbound/03_opc_client/<device>/` (legacy
layouts: `config/01_southbound/03_opc_client/`; `[[device]]` blocks inside `opc_server/server.toml`
stay valid, section 14). The stand reads turbidity from a benchtop analyzer
(`instances/stand-01`; on the bench `prism-sim` serves the same device,
`../03_tooling/02_SIMULATOR.md`):

```toml
[[device]]
name     = "lab_instrument"
protocol = "opcua"

[device.opcua]
endpoint           = "opc.tcp://192.168.1.20:4840/"
application_uri    = "urn:prism:client:lab_instrument"
security_policy    = "None"
security_mode      = "None"
pki_dir            = "../data/pki/client"
trust_server_certs = false
# certificate      = "../data/pki/client/cert.pem"   # required with encrypted security
# private_key      = "../data/pki/client/key.pem"
# username         = "prism"                        # optional pair, requires
# password_env     = "PRISM_OPC_PASSWORD"           # encrypted security
max_nodes_per_read = 100

[[device.tag]]
name      = "turbidity"
node_id   = "ns=2;s=lab_instrument.turbidity"
data_type = "real"
access    = "ro"

[[device.tag]]
name      = "sample_rate_sp"
node_id   = "ns=2;s=lab_instrument.sample_rate_sp"
data_type = "word"
access    = "rw"
```

### `[device.opcua]` key reference
- `endpoint`: Remote endpoint URL (must start with `opc.tcp://`).
- `application_uri`: Client application URI reported to the server.
- `security_policy` / `security_mode`: Same supported pairs as the server.
- `pki_dir`: Client certificate store, resolved from the `config/` root (default `../data/pki/client`).
- `trust_server_certs`: Whether server certificates are trusted automatically (section 4).
- `certificate` / `private_key`: Client certificate pair — required with encrypted security, validated at load.
- `username` / `password_env`: Optional credential pair (requires encrypted security).
- `max_nodes_per_read`: Maximum nodes per read request (1–10000).

Tags use the standard `node_id` + `data_type` + `access` properties
(`01_DEVICES.md`, section 1) and appear on the bus as `lab_instrument.turbidity`.

## 3. Declarative Generator Tooling

To eliminate manual editing of large tag dictionaries, use the declarative
generators: `prism-devtools generate opc-server|opc-client` (shipped in
`devtools/tooling/`) writes the files from the southbound tags.

### Generate OPC UA Server Nodes:
```bash
prism-devtools generate opc-server --root .
prism-devtools generate opc-server --root . --apply-hand   # apply server.toml
```
- Reads input devices declared in the `targets` of `devtools/tooling/generators/opc_server.toml` (scanning modular directories like `config/01_southbound/01_modbus`, `config/01_southbound/02_s7comm`, `config/01_southbound/04_virtual_tags`).
- Automatically aggregates split tag files across modular device folders (e.g., `plc.toml`, `buttons.toml`, `control.toml`, `telemetry.toml`).
- Performs pre-validation (checks tag collisions and duplicate addresses across all modular files).
- Automatically marks writable tags (`access = "rw"`) as `writable = true`; a `[[tag]].writable` override wins. Write-only (`wo`) tags and tags without `data_type` are skipped with a warning — the runtime cannot serve them.
- Emits a complete node address space in `config/02_northbound/02_opc_server/nodes.toml` (drift-guarded) — or, with `[generator].layout = "split"`, one file per device in `config/02_northbound/02_opc_server/nodes.d/`; on a layout switch the files of the old layout are retired to `<name>.bak` (a `--check` run reports them as drift until they are). The runtime merges it into the server exports at load (section 1).
- Seeds `config/02_northbound/02_opc_server/server.toml` (bind address, security, exposure flags) from `[defaults.server]` only when missing. `--apply-hand` applies the described `[defaults.server]` to an existing file: `.bak` on first adoption, then it is drift-guarded like `nodes.toml`; `--apply-hand --check` performs the same comparison without writing. `[[defaults.server.user]]`/`[[defaults.server.tag]]` arrays-of-tables are emitted as `[[server.user]]`/`[[server.tag]]` (hand-written exports stay available and win over `nodes.toml` on duplicates).

### Generate OPC UA Client Endpoints:
```bash
prism-devtools generate opc-client --root .
prism-devtools generate opc-client --root . --apply-hand   # apply defaults.toml
```
- Reads modular target directories specified in `devtools/tooling/generators/opc_client.toml`.
- Aggregates split tag files across device folders into unified remote endpoints; `{host}` in the `endpoint_url` template resolves from `[device.tcp].ip` (fallback `127.0.0.1`).
- Emits `config/02_northbound/04_opc_client/endpoints.toml` — or, with `[generator].layout = "split"`, one file per device in `config/02_northbound/04_opc_client/endpoints.d/` (no `endpoints.toml`; the same retirement rules as `nodes.d/`) — (drift-guarded) and seeds `config/02_northbound/04_opc_client/defaults.toml` (security policy, PKI, timeouts) only when missing.
- `defaults.toml` is described by `[defaults.security]`: any key of that section is emitted as-is (`security_policy`, `security_mode`, `pki_dir`, `trust_server_certs`, `max_nodes_per_read`, `session_timeout_ms`, `reconnect_backoff_ms`), missing keys get the generator defaults. `--apply-hand` applies the described content like above.
- Monitoring fields (`sampling_interval_ms`, `queue_size`, `discard_oldest`) cascade `[defaults.monitoring] -> [[group]] -> [[tag]]`.

## 4. Security

Both endpoints default to unencrypted `None`/`None` — acceptable only on a
trusted isolated network (the bench layout binds loopback). The runtime
refuses the dangerous combinations instead of failing silently.

### Server exposure rules

Checked by `--check-config` and at server start (`validate_security`):

- a non-loopback `host` with `security_policy = "None"` is rejected unless
  `allow_insecure_remote = true` explicitly acknowledges the risk;
- `allow_anonymous_writes = true` requires `allow_anonymous = true` and, on an
  unencrypted endpoint, the same explicit acknowledgement — by default
  **writes require an authenticated session**;
- `allow_anonymous = false` requires at least one `[[server.user]]`;
- username identities require encrypted security (`Basic256Sha256`), and every
  password comes from an environment variable (`password_env`) — the config
  file never holds a secret;
- a secure endpoint requires the `certificate` + `private_key` pair (both set,
  files present); without an explicit certificate the stack generates a
  self-signed sample keypair inside `pki_dir` (fine for `None` and bench
  diagnostics only).

### Encrypted server setup

```toml
[server]
host                   = "0.0.0.0"
security_policy        = "Basic256Sha256"
security_mode          = "SignAndEncrypt"
certificate            = "../data/pki/server/cert.pem"
private_key            = "../data/pki/server/key.pem"
allow_anonymous        = false
allow_anonymous_writes = false

[[server.user]]
username     = "engineer"
password_env = "PRISM_OPC_PASSWORD"
```

Create the instance certificate (self-signed for a closed network, or issue
one from the plant CA). The **application URI must be the FIRST subjectAltName
entry**: async-opcua matches it against the endpoint's application URI
(`urn:prism:server` for the server; for a client device — its configured
`application_uri`):

```sh
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout ../data/pki/server/key.pem -out ../data/pki/server/cert.pem \
  -subj "/CN=prism-gateway" \
  -addext "subjectAltName=URI:urn:prism:server,DNS:prism-gateway,IP:10.0.0.10"
```

`pki_dir` holds the async-opcua PKI layout; directories are created on demand:

```text
<pki_dir>/
├── own/cert.der            # application instance certificate (when generated)
├── private/private.pem     # its private key
├── trusted/                # trusted peer certificates (flat directory)
└── rejected/               # refused peers, dropped here automatically
```

The server does **not** auto-trust unknown client certificates: an unknown
certificate is refused (`BadCertificateUntrusted`) and its file appears in
`<pki_dir>/rejected/`; to trust it, move that file into `<pki_dir>/trusted/`
(async-opcua names peers as `<CN> [<SHA-1>].der`, so keep the file name).

### Client security

- `security_policy` / `security_mode` support the same pair; with
  `Basic256Sha256` the client certificate pair is **required** (validated at
  load — it is not optional). Its subjectAltName must carry the session
  application URI (`[device.opcua].application_uri`) as the first entry — the
  server validates it.
- Server certificate trust: pre-place the server certificate into the client
  `pki_dir/trusted/` (the same `<name> [<SHA-1>].der` naming — a refused
  attempt drops it into `rejected/`, from where it can be moved), or set
  `trust_server_certs = true` — the client then trusts the certificate it is
  presented with (convenient for commissioning, a man-in-the-middle risk on
  an open network).
- `username` / `password_env`: username authentication requires encrypted
  security; the password is read from the environment at connect time.
